# 체크리스트: 아키텍처 설계 (SWE.2)
기준: A-SPICE 프로세스 SWE.2 (사용 중인 A-SPICE 버전의 문서와 대조해 갱신할 것), 스킬 `architecture-design`

| ID | 항목 | 근거 |
|---|---|---|
| ARC-01 | 모든 컴포넌트에 ID, 책임 한 문장, 할당된 `SWR`이 있다. | SWE.2 BP: 아키텍처 개발 |
| ARC-02 | 모든 `SWR`이 하나 이상의 컴포넌트에 할당되어 있다. | SWE.2 BP: 요구사항 할당, 추적성 |
| ARC-03 | 모든 컴포넌트에 인터페이스가 정의되어 있다. | 프로젝트 규칙 |
| ARC-04 | 인터페이스 정의에 시그니처, 반환값 의미, 사전/사후 조건, 호출 규칙, 오류 처리가 있다. | SWE.2 BP: 인터페이스 정의 |
| ARC-05 | 컴포넌트 간 연결이 모두 인터페이스를 통한다 (직접 내부 접근·전역 공유 없음). | 프로젝트 규칙 |
| ARC-06 | 순환 의존이 없다. | 결합도 |
| ARC-07 | 각 컴포넌트의 책임이 한 문장으로 설명되고 응집도가 높다. | 응집도 |
| ARC-08 | 의존이 인터페이스 하나로 좁혀져 있다 (낮은 결합도). | 결합도 |
| ARC-09 | 모듈화·캡슐화 원칙이 지켜진다 (내부 상태 비공개). | 프로젝트 규칙 |
| ARC-10 | SOLID(단일 책임, 개방-폐쇄, 리스코프, 인터페이스 분리, 의존 역전) 위반이 없다. | 프로젝트 규칙 |
| ARC-11 | 동적 동작(초기화, 주기, 오류 시 순서)이 필요한 범위에서 기술되어 있다. | SWE.2 BP: 동적 동작 |
| ARC-12 | 설계 결정의 근거와 대안이 기록되어 있다. | SWE.2 BP: 평가 |
| ARC-13 | 요구사항↔`ARCH`↔`IF` 양방향 추적성이 매트릭스로 확인된다. | 양방향 추적성 |
| ARC-14 | 품질·제한·제약 요구사항이 설계에서 만족되는 방식이 드러난다. | 일관성 |
