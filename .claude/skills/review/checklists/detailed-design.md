# 체크리스트: 상세 설계 (SWE.3)
기준: A-SPICE 프로세스 SWE.3 (사용 중인 A-SPICE 버전의 문서와 대조해 갱신할 것), 스킬 `detailed-design`

| ID | 항목 | 근거 |
|---|---|---|
| DD-01 | 모든 컴포넌트가 모듈로 분해되어 있고 모듈마다 ID와 책임 한 문장이 있다. | SWE.3 BP: 상세 설계 개발 |
| DD-02 | 인터페이스 정의 기준(호출 함수 둘 이상, `IF` 구현, 상태 소유, 외부 자원 접근)에 해당하는 모듈에 인터페이스가 정의되어 있다. | 프로젝트 규칙 |
| DD-03 | 기준에 해당하지 않아 인터페이스를 생략한 모듈은 그 판단이 기록되어 있다. | 프로젝트 규칙 |
| DD-04 | 인터페이스가 있는 모듈은 인터페이스를 통해서만 접근된다 (내부 함수·데이터 `static`, `extern` 데이터 없음). | 프로젝트 규칙 |
| DD-05 | 모듈과 함수가 단일 책임 원칙을 지킨다 (변경 이유가 하나). | 프로젝트 규칙 |
| DD-06 | 이름이 의도를 드러내고 매직 넘버·불명확한 약어가 없다. | 클린코드 |
| DD-07 | 함수가 작고 한 추상화 수준에 머무르며 매개변수가 과하지 않다. 설계한 동작이 순환복잡도 10 이하, 80라인 이하로 구현될 크기이다. | 클린코드, CLAUDE.md 2.3 |
| DD-08 | 중복 로직이 없다. | 클린코드 |
| DD-09 | 모든 함수에 입출력, 동작, 반환값(정상·오류 값 목록), 오류 처리가 기술되어 있다. | SWE.3 BP: 동적 동작 기술 |
| DD-10 | 설계상 `void` 반환 함수가 없다. | 스킬 `implementation` |
| DD-11 | 상위 아키텍처(`ARCH`, `IF`)와 모순되지 않는다. | SWE.3 BP: 일관성 |
| DD-12 | `SWR`↔`ARCH`↔`MOD`↔`FUNC` 양방향 추적성이 매트릭스로 확인된다. | 양방향 추적성 |
