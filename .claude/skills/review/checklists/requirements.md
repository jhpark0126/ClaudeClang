# 체크리스트: 소프트웨어 요구사항 (SWE.1)
기준: A-SPICE 프로세스 SWE.1 (사용 중인 A-SPICE 버전의 문서와 대조해 갱신할 것), 스킬 `requirements-analysis`

| ID | 항목 | 근거 |
|---|---|---|
| REQ-01 | 모든 요구사항에 고유 ID가 있다. | SWE.1 BP: 요구사항 구조화 |
| REQ-02 | 모든 요구사항이 기능 / 품질 / 제한 / 제약 중 하나로 분류되어 있다. | 프로젝트 규칙 |
| REQ-03 | 기능 안전 요구사항이 본문에 없고 별도 문서의 `SSR` ID로만 참조된다. | 프로젝트 규칙 |
| REQ-04 | 품질 요구사항마다 ISO 25010 특성이 지정되어 있다. | 프로젝트 규칙, ISO 25010 |
| REQ-05 | 각 요구사항이 하나의 사항만 말한다 (원자성). | SWE.1 BP: 요구사항 분석 |
| REQ-06 | 모호어(적절히, 빠르게, 충분히 등)가 없다. | 검증 가능성 |
| REQ-07 | 모든 요구사항에 측정·시험 가능한 검증 기준이 있다. | SWE.1 BP: 검증 기준 |
| REQ-08 | 요구사항이 구현 방법이 아니라 필요한 동작·성질을 기술한다. | 프로젝트 규칙 |
| REQ-09 | 요구사항 사이에 모순·중복이 없다. | SWE.1 BP: 일관성 |
| REQ-10 | 모든 요구사항이 상위 요구사항/출처로 추적된다 (상향). | SWE.1 BP: 양방향 추적성 |
| REQ-11 | 분석 게이트: 모든 요구사항이 하향 추적 열(design/code/unit/integration/system)을 가질 자리가 `trace.csv`에 있고, 상위 ID(OEM)와 SWR/SSR 연결이 있다. 하위 열의 값은 해당 단계 게이트에서 채우며, 채워지지 않은 열은 그 단계 리뷰(ARCH-/DD-/CODE-/UT- 추적 항목)와 이터레이션 완료 게이트(`ci/requirement_coverage.sh`)에서 막는다. (사용자 결정 2026-11-27) | SWE.1 BP: 양방향 추적성 |
| REQ-12 | 추적 매트릭스를 실제로 열어 누락·고아 항목이 없음을 확인했다. | 양방향 추적성 |
| REQ-13 | 요구사항의 영향 분석과 변경 이력이 남아 있다. | SWE.1 BP: 영향 분석 |
